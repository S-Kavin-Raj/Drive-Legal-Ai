# Frontend & Android Railway Endpoint Verification Report

## Summary
The DriveLegal AI frontend now uses a centralized Railway API base URL:

- `https://drive-legal-ai-production.up.railway.app`

The hardcoded development backend URL in the frontend source has been removed from the app API client and replaced with a centralized configuration source.

## Current verification result
### Source-controlled app code
- No remaining source-level references to `http://localhost:4000`, `127.0.0.1`, or `10.0.2.2` were found in the frontend app source after the update.
- All API-backed frontend services now inherit the Railway base URL through the shared Axios client.

### Android Capacitor assets
- The synced Android Capacitor asset config reflects the Railway host.
- The app bundle generated by Capacitor now uses the Railway base URL in the app API client.

### Note on generated build artifacts
- Some generated Gradle/intermediate build artifacts may still contain generic `localhost` strings from third-party libraries or older build outputs.
- These are not the app’s API base URL and are not part of the checked-in source path used by the Capacitor runtime.

## Files changed
### Source files
- `frontend/src/services/apiConfig.js`
  - New centralized API configuration file.
  - Defines the Railway default base URL and normalizes any env override.

- `frontend/src/services/apiClient.js`
  - Updated to consume the centralized `API_BASE_URL`.
  - No longer hardcodes `http://localhost:4000`.

- `frontend/.env`
  - Added `VITE_API_URL=https://drive-legal-ai-production.up.railway.app`.

- `frontend/capacitor.config.json`
  - Updated Capacitor navigation config to include the Railway host.

### Android Capacitor sync outputs
- `frontend/android/capacitor.settings.gradle`
  - Refreshed by Capacitor sync.

- `frontend/android/app/capacitor.build.gradle`
  - Refreshed by Capacitor sync.

## Deployment note
The project is now configured so the frontend and Android Capacitor shell use Railway as the default backend. If deployment environments need a different API host later, they can override it with `VITE_API_URL`, but the checked-in default now points to Railway.
